fix(build-loader): purger le cache buildx apres chaque version (disque sature en CI)

Les runners GitHub-hosted n'ont qu'environ 14 Go libres. Sur un backfill de
centaines de versions en multi-arch (amd64+arm64), le cache buildx
s'accumule version apres version (peu de reutilisation possible hormis les
couches de base JAVA_IMAGE/JAVA_RUNTIME_IMAGE, chaque MC_VERSION produisant
des couches RUN differentes) et finit par saturer le disque, faisant
echouer un build arbitraire plus loin dans la liste.

Symptome observe en CI sur plusieurs runs consecutifs : vanilla (1.6, puis
1.4.2), bukkit (1.8.3) echouent a des versions differentes a chaque
tentative, toutes reproduites avec succes en local (single et multi-arch).
Ce caractere non reproductible et aleatoire, a une version differente a
chaque fois, est caracteristique d'un epuisement de ressource (disque)
plutot que d'un bug de version specifique.

Ajout d'un `docker buildx prune -f --keep-storage 20GB` apres chaque
version construite (garde les couches de base en cache, purge le reste),
et d'un diagnostic d'espace disque (`df -h`, `docker system df`) affiche en
cas d'echec pour faciliter le debug futur si le probleme persiste.
